# caduceus-web — Agent Memory

## Stack

- **Package manager:** pnpm
- **Framework:** React 19 + Vite 8
- **Routing:** TanStack Router (file-based, `src/routes/`)
- **Data fetching:** TanStack Query (v5, `src/queries/`)
- **Styling:** TailwindCSS 4 + shadcn/ui (Radix UI + CVA + clsx + tailwind-merge)
- **Icons:** lucide-react
- **State:** Zustand (quiz store)
- **Format/Lint:** oxlint + oxfmt (via pnpm exec)
- **Deploy:** Vercel (NOT Cloudflare Pages — wrangler.jsonc is a template artifact)

## Auth

### Token management

- Stored in `localStorage` as key `caduceo_token`
- Set via `setToken()`, removed via `clearToken()` in `lib/api.ts`
- API client reads token from localStorage and sets `Authorization: Bearer <token>` header
- Token auto-exists in localStorage until explicit logout

### Auth hooks

| Hook | Returns | Description |
|---|---|---|
| `useSession()` | `{ data: User, isLoading }` | Auto-fetches `/me` if token exists |
| `useLogin()` | mutation | Login with email/password → stores token + user |
| `useRegister()` | mutation | Register → stores token + user |
| `useLoginWithGoogle()` | mutation | Google login → stores token + user |
| `useLogout()` | mutation | Clears token + query cache |

### Logout — navigation

**IMPORTANT:** `useLogout().mutate()` clears the token and query cache but does NOT navigate automatically. Each call site must handle navigation:

```typescript
logout.mutate(undefined, {
  onSuccess: () => router.navigate({ to: '/auth/login' }),
});
```

Current call sites:
- `app-shell.tsx` (sidebar logout button) ✅ navigates
- `settings-page.tsx` (settings logout button) ✅ navigates

### Auth response shape

```typescript
interface AuthResponse {
  token: string;
  user: {
    id: string;
    name: string;
    email: string;
    role: number;  // 0 = user, 1 = admin
    tier: number;  // 0 = free, 1 = plus
    avatar_url?: string;  // only present for Google users
  };
}
```

## Google OAuth

### How it works

1. `GoogleButton` component loads Google Identity Services (GIS) script
2. Google renders its branded "Continuar con Google" button
3. On click, Google popup handles consent
4. Google returns credential (ID token JWT) via callback
5. Frontend sends `{ id_token: credential }` to `POST /api/v1/auth/google`
6. Backend verifies token, creates/links/logs in user, returns JWT

### GoogleButton component (`src/components/ui/google-button.tsx`)

- Lazy-loads GIS script on first mount
- Renders Google button inside a controlled container
- `onSuccess` callback receives the credential (ID token)
- Shows loading state while pending
- Requires `VITE_GOOGLE_CLIENT_ID` env var — renders nothing if missing

### Env vars

| Variable | Where | Notes |
|---|---|---|
| `VITE_GOOGLE_CLIENT_ID` | Vercel (production) + .env (dev) | Public — visible in browser |
| `VITE_API_URL` | Vercel + .env (dev) | API base URL, defaults to `http://localhost:3000` |

## Query Architecture

Each domain follows the same pattern:

```
queries/<domain>/
├── types.ts    # DTOs and params types
├── service.ts  # Raw API calls (api.get/post/patch/delete)
├── hooks.ts    # TanStack Query hooks (useXxx)
├── keys.ts     # Query key factory
└── index.ts    # Re-exports
```

### Example — auth domain

```typescript
// types.ts
export type LoginParams = { email: string; password: string };
export type GoogleLoginParams = { id_token: string };

// service.ts
export const login = async (params: LoginParams): Promise<AuthResponse> => {
  const data = await api.post<AuthResponse>('/api/v1/auth/login', params);
  setToken(data.token);
  return data;
};

// hooks.ts
export const useLogin = () => {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (params: LoginParams) => login(params),
    onSuccess: (data) => {
      queryClient.setQueryData(authKeys.session(), data.user);
    },
  });
};
```

## Routing

- **File-based** via TanStack Router plugin
- Public routes: `/auth/login`, `/auth/register`, `/`
- Protected routes: `/app/*` (wrapped in AppShell + `useSession`)
- Admin routes: `/admin/*`

## UI Components (shadcn/ui)

Components in `src/components/ui/` are based on shadcn/ui with the following setup:
- `cn()` utility from `tailwind-merge` + `clsx`
- `cva` for component variants
- Radix UI primitives for interactive components
- TailwindCSS v4 with `@tailwindcss/vite` plugin

## API Client (`src/lib/api.ts`)

- `api.get<T>(path)`, `api.post<T>(path, body)`, `api.patch<T>(path, body)`, `api.put<T>(path, body)`, `api.delete<T>(path)`
- Auto-attaches `Authorization: Bearer <token>` from localStorage
- Auto-parses JSON errors into `Error` objects
- Returns `undefined` for 204 responses

## Deployment

- **Platform:** Vercel (auto-deploys from git)
- **The `wrangler.jsonc` file is a template artifact** — don't use `npm run deploy` (it tries to deploy to Cloudflare via wrangler and fails)
- Instead, push to git and Vercel auto-deploys, or use `vercel deploy --prod`
- Set VITE_* env vars in Vercel Dashboard → Project → Settings → Environment Variables
